# 跨来源内容去重审计

## 目标

在不调用 AI、不修改生产数据的前提下，识别同一内容在不同来源中的重复发布，为后续数据库唯一约束和跨来源关联提供阈值依据。

## 当前审计链路

1. 同一数据源内比较 `sourceId + externalId`。
2. URL 标准化后执行精确比较。
3. 标题执行 Unicode NFKC、大小写、空格、标点和常见快讯前缀归一化。
4. 提取模型版本、日期、金额、百分比等关键数字。
5. 短标题使用字符 2-gram，其他标题使用字符 3-gram。
6. 同时计算 Jaccard、Levenshtein 编辑相似度与 64 位 SimHash 汉明距离。

全部计算在本地完成，不使用 Embedding 或大模型。

## 默认阈值

- 自动重复：Jaccard 或编辑相似度不低于 0.92，或 Jaccard 不低于 0.82 且 SimHash 距离不大于 3。
- 疑似重复：Jaccard 或编辑相似度不低于 0.82，或 Jaccard 不低于 0.72 且 SimHash 距离不大于 6。
- 跨来源自动重复时间窗口：24 小时。
- 同一来源近似标题自动重复时间窗口：6 小时。
- 疑似重复人工复核窗口：最近 7 天。
- 自动重复要求关键数字完全一致。
- 同一来源的相同标题默认进入人工复核，避免把每日早报等周期栏目自动合并。

## 运行方式

审计脚本从标准输入读取 JSON 数组，不直接连接数据库：

```bash
pnpm --filter @intellipick/test-scripts audit:dedup < contents.json
```

可调参数：

```text
--automatic-threshold=0.92
--review-threshold=0.82
--automatic-max-hours=24
--same-source-automatic-max-hours=6
--max-hours=168
--max-candidates=200
```

NAS 数据应通过只读 SQL 导出，并将最终报告保存到用户输出目录，不写入仓库运行配置或生产数据库。

## 正式落地前验收

- 至少人工检查 50 组候选。
- 自动重复的人工确认准确率不低于 95%。
- 不得自动合并版本号、日期、金额或百分比不同的内容。
- 数据库变更必须保留所有来源 URL，不直接删除后出现的来源记录。
- 正式上线前增加 `(source_id, external_id)` 唯一约束和并发冲突测试。

## 2026-08-27 真实数据审计

NAS 最近 7 天共有 1,651 条带标题内容，覆盖 10 个数据源，共比较 1,362,075 个组合，约 4 秒完成。

第一轮使用 7 天自动合并窗口：

- 自动重复 17 组。
- 其中 2 组为不同日期的 ETF 净流入和成交额行情，人工准确率约 88%。
- 该阈值不满足自动合并要求。

收紧为“跨来源 24 小时、同来源 6 小时”后：

- 自动重复 12 组，人工检查均为同一事件。
- 疑似重复 36 组，继续保留人工复核。
- 共发现 26 组跨来源候选。
- 日期不同、涨跌相反、币种不同、公司不同的标题均未进入自动重复。

当前 12 组自动样本的人工准确率为 100%，但样本数量仍不足 50 组。正式阶段应先写入“重复候选标记”，暂不自动隐藏或合并；累计足够样本后再开启自动处理。

## 生产接入方式

生产阶段新增 `content_duplicate_candidates` 表，只记录重复候选，不修改内容表的展示状态：

- 每条新内容入库后，与最近 7 天内容执行一次本地比较。
- 候选记录保存分类、原因、Jaccard、编辑相似度、SimHash 距离、长度比例、关键数字匹配和时间差。
- 候选状态默认为 `pending`，后续可更新为 `confirmed` 或 `dismissed`。
- 内容仍然全部保留，主页暂不隐藏或合并。
- 候选内容 ID 始终按字典序保存，避免同一对内容产生两条反向记录。

`contents` 表增加 `(source_id, external_id)` 唯一索引，防止同一来源的同一条内容在并发任务中重复插入。调度器和 Pipeline 的精确去重同步调整为：

- URL 仍可跨来源精确去重。
- 外部 ID 只在同一数据源内比较。
- AI Filter 停用后，隔离区不再阻止重新采集；仍在当前 Feed 中的历史隔离内容会自然完成一次实体提取并入库。
